# 擴充為多檔組合，並把持倉存在裝置上

課堂題目從「單一個股的盈虧」擴充為「我一共賺了還是虧了」：輸入多筆持倉，每筆有股票代號、買入價與數量，輸出整個組合的總盈虧與收益率。原本的單檔多批次是新模型的子集，因此直接取代，不保留兩種模式 —— 兩個模式會讓介面與狀態複雜度翻倍，而多檔已涵蓋單檔。

## 持倉改為保存

ADR-0012 決定不保存持股，理由是那會連帶長出 CRUD、列表、刪除、空狀態與資料遷移，而這些跟核心問題無關。多檔模式讓這個理由失效：列表與增刪本來就是這次的需求，省不掉；不保存能省下的只剩寫入 localStorage 那幾行。

另一邊，輸入成本的差距很大。單檔是三個欄位，重打不痛；五檔就是十五個欄位，每次開啟都要重打，沒有人會用第二次。

但界線要劃清楚：只存「使用者輸入過的持倉」，不存歷史、不做損益走勢、不跨裝置同步。跨過那條線，這個工具就從有記憶的計算機變成持股追蹤服務，那是 ADR-0006 明確排除的方向。資料帶 schema 版本，讀到不認識的版本就當作沒有資料，不嘗試遷移 —— 這是本機計算用的輸入值，不是帳本，重打比遷移錯誤安全。

## 手續費改為逐筆計算

券商手續費的最低收費是以「每一張委託單」為單位，不是每一檔股票，更不是整個組合。同一檔分三次買進就是三張委託、三筆手續費，各自適用最低收費。

把同一檔的批次成本加總後才算費用，會讓小額批次的最低收費被吃掉。實例：0050 分別買 500 股 @100、300 股 @95、100 股 @106，六折費率下逐筆是 42 + 24 + 20（第三筆不足最低收費）＝ 86；若先加總成 89,100 再算只有 76。批次愈多、金額愈零碎，低估愈嚴重。

賣出則假設整個部位一次賣出，所以每檔只算一筆賣出手續費。證交稅沒有最低收費，逐筆或整筆結果相同，但稅率仍須逐檔判斷是否為 ETF。

組合層級的做法因此是「每檔各自算完再加總」，而不是把組合總額丟進同一個公式。報酬率的分母是全部實際投入的錢，含每一筆的買進手續費。
