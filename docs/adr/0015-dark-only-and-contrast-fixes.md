# 只做深色模式，並修正照搬 lifelio 色票帶來的對比問題

介面確定只做深色，不跟隨系統切換，淺色那一組變數整個移除。單一主題讓色票可以針對深色底仔細調，不必在兩套之間折衷；App 也不會因為使用者的系統設定而長得不一樣。

實際在畫面上量測後，發現 ADR-0014 直接照搬 lifelio 的值造成三個問題，都已修正：

- **字級掉到 11px。** lifelio 的 `html { font-size: 14px }` 搭配 Tailwind 的 rem-based `text-xs`（0.75rem）會得到 10.5px。lifelio 自己用一整段 px 覆寫把字級釘死，並在註解寫明「低於 12px 就是 bug」，而 ADR-0014 只抄了基準字級、沒抄那段覆寫。這裡改成基準 16px，`text-xs` 自然落在 12px，不需要逐條覆寫，也符合行動裝置的內文下限。
- **元件邊界看不見。** 卡片邊框對卡片底只有 1.3:1，WCAG 1.4.11 要求必須被辨識的元件邊界達 3:1。拆成兩個 token：表單控制項用 `--input-border`（量得 3.22:1，達標），卡片與分隔線用較暗的 `--border`，因為純裝飾性的分隔不在該條款範圍內，全部拉到 3:1 會讓整個介面變成鐵絲網。
- **輸入框在手機上沒有邊框。** 批次面板為了視覺乾淨把邊框設成 `border-transparent` 搭配 `hover:border-border`，但觸控裝置沒有 hover，實機上等於沒有欄位邊界。改為靜止狀態就使用 `--input-border`。

文字顏色本身沒有問題：全畫面掃描後沒有任何一項低於 WCAG AA，最低的是 12px 次級文字的 5.26:1。量測時要注意色彩是以 `oklch()` 回報的，直接用正規表示式取數字會得到完全錯誤的比值，必須先讓瀏覽器換算成 sRGB。
